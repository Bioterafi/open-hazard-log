Open Hazard Log by Bioterafi GitHub

A hazard log that keeps up with the product it describes.

Open Hazard Log is an open-source tool for Clinical Safety Officers working to DCB0129 and DCB0160. An agent reads your specifications and code and suggests hazards, quoting its sources. Simple checks notice when the evidence behind a control changes. Nothing enters the log until you approve it.

Star on GitHub

Why

A hazard log is meant to live as long as the system it describes. Most are written for go-live, kept in a spreadsheet, and left behind as the product changes.

Controls quietly lose the tests and documents they relied on. The links between a hazard, its causes, its controls and their evidence sit in free text that nobody can check. Hazards passed from a manufacturer to a deploying organisation get lost in email.

How it works

  1. 1ScanAn agent reads the intended use, specifications and the code you choose, and proposes hazards. Each one quotes its sources; a proposal with no quote that can be found word for word is never shown.Tested in test_scan.py
  2. 2ReviewYou rate each new hazard before you see the agent's rating, then approve, edit or reject it. Your reasons go into the next scan.Tested in test_review.py
  3. 3CheckWith no AI involved, the evidence behind each control is re-hashed and new commits are matched to the code each hazard depends on. Whatever changed comes back to you.Tested in test_checks.py
  4. 4IssueYou sign numbered, frozen versions of the log and export them in the NHS hazard log template layout.

What it won't do

  • Change the log without youThe agent and the checks can only make proposals, and the test suite fails if that ever changes. Every change in the log carries a named person and a tamper-evident audit trail.Tested in test_scan.py, test_checks.py, test_core.py
  • Replace your safety processThe scan supplements a hazard workshop. Your Clinical Risk Management Plan and Safety Case Report stay yours.
  • Touch patient dataIt reads documents and code, and only after you confirm they contain none.Tested in test_scan.py
  • Live on someone else's serverIt runs on your own computer, and answers only requests from that computer, however it is started.Tested in test_web.py, test_local_server.py

Grounded in the standards

DCB0129 3.3.1A hazard log maintained for the life of the system
DCB0129 3.3.2The CSO approves each version: Issue version signs and freezes it
DCB0129 4.3.1Known and foreseeable hazards identified: the scan proposes, the CSO decides
DCB0129 4.4.1Risk derived from your own matrix; only the CSO sets ratings
DCB0129 6.3Controls verified, with their evidence re-checked by hash
DCB0129 7.3.4An audit trail of every version and change
DCB0160 2.5.1A list of deployer actions for the deploying organisation's own log

Based on the 2018 versions of both standards, which NHS England is reviewing. The risk matrix and template columns are configuration, so they can follow the revision. Open Hazard Log supports clinical risk management; it doesn't make a product compliant, and it isn't affiliated with or endorsed by NHS England.

Try it

Open Hazard Log is open source under the Apache-2.0 licence. The code, its tests, and Open Hazard Log's own hazard log are at github.com/Bioterafi/open-hazard-log. To try it with made-up data, without an API key:

git clone https://github.com/Bioterafi/open-hazard-log
cd open-hazard-log
uv sync
./scripts/demo.sh
uv run ohl --db demo.db serve --as cso@demo.local
